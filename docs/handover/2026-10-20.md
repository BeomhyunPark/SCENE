# 인수인계 (2026-10-20)

기준은 `main` `da91a00`이다. 이 문서는 그날의 구현 기록이지 제품 결정이 아니다. 여기와 [제품 결정](../product/PRODUCT_DECISIONS.md), [API](../../backend/docs/api.md)가 다르면 그 두 문서가 이긴다. 결정 문서와 `docs/architecture/`는 이 기록 때문에 고치지 않는다.

## 지금 되는 일

운영자는 개발용 로그인으로 들어와 행사를 만들고, 신청서를 열고, 업무를 다루고, 초대 링크로 들어오고, 조직에서 나가고, 행사를 종료할 수 있다. 참가자는 계정 없이 신청하고, 한 번 받은 접근 키로 다시 들어온다.

공개 가입, 비밀번호, 조직 찾기, 조 편성, 일정, 공지, 현장 체크인, Export는 화면이 정적이다. 서버에도 그 경로는 없다.

로컬 서버는 [backend/README.md](../../backend/README.md)다. `docker compose up -d --wait` 다음 `./gradlew bootRun --args='--spring.profiles.active=local'`. 프론트는 `frontend/`에서 `corepack pnpm`이다. `pnpm`은 PATH에 없다. `VITE_API_MOCK=1`일 때만 MSW다. 그 외 개발 서버는 로컬 API로 간다.

시드에 비밀번호는 없다. 로그인은 `POST /api/v1/operator/auth/login`에 `userId`와 선택 `email`이다. 화면의 개발용 로그인이 그 호출이다.

| id | 시드 |
| --- | --- |
| `…0001` | Local owner. 공간 OWNER, 행사 OWNER |
| `…0002` | Local manager |
| `…0003` | Local staff |
| `…0010` | Local space |
| `…0020` | Local event. 시드 SQL은 `DRAFT` |

시드는 같은 행을 다시 넣지 않는다. 볼륨을 쓴 적 있으면 시드 파일과 다를 수 있다. 비울 때는 `docker compose down -v`. 시드 행사로 종료, 탈퇴, 신청 POST를 시험하지 않는다.

## 연결된 화면

운영 화면은 `RequireOperator` 안이다. 세션이 없으면 `/login`으로 간다.

| 주소 | 하는 일 | 머지 |
| --- | --- | --- |
| `/events`, `/events/new`, `/events/:eventId` | 공간의 행사 목록, 생성, 홈. 기간·장소·유형은 만들 때 저장된다. 이후 PATCH는 이름만 받는다 | #180 |
| `/events/:eventId/tasks` | 업무 목록·추가·담당·완료·다시 열기·취소·삭제. 제안은 고정 템플릿이고 고른 제목만 보낸다 | #182 |
| `/events/:eventId/participants/setup` | 행사당 신청서 하나. 질문 추가·수정·삭제, 신청 열기·닫기. 질문 라벨의 개인정보 경고는 로컬 규칙이고 저장을 막지 않는다 | #184 |
| `/operator/invitations` | 초대 미리보기와 수락. 토큰은 fragment에서 읽고 바로 지운 뒤 30분 localStorage | #186 |
| `/settings`, `/spaces/:spaceId/leave` | 조직에서 나가기. 유지할 행사를 고른다. 조직 사이드바의 설정이 입구다 | #190 |
| `/events/:eventId/settings`, `/end`, `/retrospective` | Owner가 진행 중 행사를 종료하면 종료 홈. 다시 열기·보관·대행 사유는 화면에 없다. 회고 쓰기는 `ENDED`만 | #192 |
| `/events/:eventId/participants` | 신청이 열려 있으면 키 없는 신청 주소를 복사한다 | #194 |

참가자와 초대는 `RequireOperator` 밖이다.

| 주소 | 하는 일 |
| --- | --- |
| `/apply/:eventId/:formId` | 공개 신청서. 이름과 전화가 필수다. 201의 접근 키는 그 화면에 한 번 나온다 |
| `/participate/:eventId` | 키는 fragment만. 첫 렌더에서 `history.replaceState`로 지우고 세션 POST 본문으로만 보낸다. 저장소에 넣지 않는다 |
| 입장 후 | `GET /api/v1/participant/me`의 이름과 로그아웃만. 공지·일정·행사 이름은 호출하지 않는다 |

신청, 세션, `me`, 로그아웃은 서버에 있다. MSW를 `unverified`로 표시하지 않았다. 회고 `GET/PUT /api/v1/operator/events/{eventId}/retrospective`만 `unverified`다. 없는 회고 경로는 404가 아니라 코드 없는 500 unexpected이고, 화면은 아직 없는 글로 본다. 저장이 서버에 반영됐다고 말하지 않는다.

## 서버는 있고 화면은 없는 것

[api.md](../../backend/docs/api.md)에 있고 화면이 호출하지 않는다.

- 초대 생성, 재발송, 취소. 화면은 미리보기와 수락만 한다.
- 운영자 추가·역할·권한 편집. 화면은 권한 조회와 행사 Owner 판별만 한다.
- 소유권 이전 요청·수락·거절·취소.
- 신청 목록과 신청 한 건 읽기. 참가자 화면은 신청이 있어도 "아직 참가자가 없어요"로 남는다.
- `reopen`, `archive`, `unarchive`. 종료 화면은 일부러 숨겼다.
- 공간 소유자의 상태 변경 대행. 화면은 `override.reason`을 보내지 않는다.

## 서버에도 없는 것

[api.md](../../backend/docs/api.md)의 "아직 없는 경로"와 같다.

- 비밀번호 로그인, SMTP
- 체크 항목 추가
- `GET /api/v1/participant/me` 밖의 참가자 조회. 공지와 일정 읽기도 없다
- 회비, 조, 방, 차량, 체크인, Export, 회고, 공간 설정
- 기간·장소·유형을 바꾸는 PATCH
- 공간 소유권 이전 URL
- 접근 키를 다시 발급하는 URL

DEC-064 문서와 API 설계는 참가자 세션을 Phase 3로 적는다. 서버와 화면은 세션, `me`, 로그아웃을 이미 연다. 그 차이는 api.md "결정 문서와 다른 점"에 있다. SMS와 인증번호는 이 범위에 없다.

## 눌러도 아직 안 가는 곳

- 조직 사이드바는 설정만 `/settings`로 간다. 행사, 알림, 기록, 준비 업무, 안내, 일정, 현장 운영, 참가자, 운영 멤버, 연동은 버튼이고 주소가 없다. 사이드바 접기도 동작하지 않는다.
- 행사 안 사이드바의 "다른 운영 시작"과 "설정"도 주소가 없다. 종료와 회고는 헤더의 "행사 설정"과 종료 홈으로 간다.
- 행사 홈의 "일정 정리"는 주소가 없다. 참가자·준비 업무 메뉴는 그 화면을 한 번 연 뒤 `sessionStorage`에 남는다. 주소를 직접 열면 메뉴가 없어도 화면은 나온다.
- 참가자 화면의 "QR로 공유하기"와 "참가자 직접 추가"는 신청 설정으로 가지 않는다.
- `/`, `/signup`, `/verify-email`, `/find-organization`, `/join-pending`, `/register-organization`, `/forgot-password`, `/reset-password`는 서버를 호출하지 않는다. 메일 확인의 확인과 나중에 하기는 `/find-organization`으로 가고, 초대 화면으로 돌아오지 않는다.

## 다음 변경에서 깨지기 쉬운 것

- `main`에 직접 커밋하지 않는다. 작업 브랜치에서 PR로 올리고, 스쿼시 머지는 `gh api`의 `merge_method=squash`다.
- 오류 분기는 RFC 9457 `code`다. `detail`을 화면에 내지 않는다.
- 브라우저 요청은 [frontend/src/api/client.ts](../../frontend/src/api/client.ts)만 쓴다. 변경 요청은 CSRF 쿠키 `XSRF-TOKEN`과 헤더 `X-XSRF-TOKEN`이다.
- 없는 경로는 MSW에 `unverified`로 표시하고 PR에 적는다. 있는 경로를 그렇게 표시하지 않는다.
- 색은 `var(--color-*)`, 글자는 `var(--scene-*)`다. 버튼은 [frontend/src/components/Button.tsx](../../frontend/src/components/Button.tsx)다. 화면 문장은 해요체다.
- 접근 키는 fragment와 세션 POST 본문 밖에 두지 않는다. 초대 토큰의 localStorage를 키에 복사하지 않는다.
- 새 화면에서 `react-hook-form`과 `zod`를 쓰지 않는다. 패키지에는 남아 있다.
- 테스트에서 `findByRole`을 fake timer로 감싸지 않는다. 알려진 단독 통과 지연은 OperatorEntry, EventTasks, TaskSuggestionPanel의 `findByRole` 시간 초과다.

프론트 확인은 `frontend/`에서 `corepack pnpm test`, `lint`, `typecheck`다. 백엔드는 `backend/`에서 `./gradlew check`다. 문서만 바꾼 PR은 docs-check와 `ci-ok`를 본다.

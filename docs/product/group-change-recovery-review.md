## 참가 정보 변경·취소·복귀

이름·연락처 등 배정의 유효성을 깨지 않는 변경은 기존 배정을 유지한다. 참석 시간·참가 상태 등 편성 판단에 영향을 주는 변경도 즉시 조에서 빼지 않는다. **배정 검토 필요**와 변경 영향을 표시하고 운영자가 유지·이동·미배정을 결정한다.

참가 취소는 예외다. 재공개를 기다리지 않고 활성 편성·공개 명단·조장 조회 대상에서 즉시 제외한다. #6의 이전 공개본 유지보다 현재 참가 자격·접근 상태가 우선한다. 과거 배정 기록은 보존한다. 기록 보존은 일반 조장에게 취소자의 개인정보를 계속 제공하는 근거가 아니다.

취소 철회·복귀 시 과거 조를 자동 복원하지 않는다. 이전 배정은 운영자 참고값으로 보여주고 운영자가 확인한다. 자동 복귀 배정이나 참가자에게 과거 조를 현재 배정으로 표시하는 동작을 추가하지 않는다.

## 이동 영향과 관련 업무

이동은 참가자 배정·이전/신규 조장 조회 대상·조별 인원/구성·조 단위 안내 대상·배정을 참조하는 운영정보에 미치는 영향을 식별해 보여준다. 숙소·차량 등은 실제 의존 관계가 있을 때 재검토 대상으로 안내한다. 조가 바뀌었다고 숙소·차량을 무조건 자동 변경하지 않는다.

작업본 이동은 #6대로 다시 공개하기 전까지 일반 참가자·조장의 공개 편성을 바꾸지 않는다. 공개 시 새 편성에 따른 조회 범위를 적용한다. 취소·현재 권한 회수는 공개 대기 없이 접근에 반영한다. 영향 감지 범위·참조 관계·조장 identity·권한 계약은 후속 기술 설계에서 정한다.

## 저장·공개 동시성

오래된 편집이 최신 저장을 조용히 덮어쓰는 방식을 금지한다. 충돌 시 최신 상태와 내 변경을 비교하고 같은 참가자·같은 배정의 충돌은 사용자 확인 후 해결한다. 충돌이 없고 안전하게 병합할 수 있으면 변경을 유지할 수 있다. 판단하기 어려우면 저장을 거절하고 최신 상태를 비교한다.

화면을 열었다는 이유로 전체 편성을 독점 잠그지 않는다. 다른 운영자의 편집 중 표시는 보조 제안이며 필수 Presence 기능으로 확정하지 않는다.

공개 확인 이후 현재 편성이 달라졌다면 공개를 막고 최신 내용을 다시 확인하게 한다. 사용자 확인은 충돌 검사를 생략한 강제 덮어쓰기 권한이 아니다. 재확인·저장·공개까지 서버가 버전 기준을 검사해야 하며 버전 단위·병합 방식·request 형식은 상세 계약에서 정한다.

## 실패·결과 불명·재시도

| 상태 | 사용자 안내·처리 |
| --- | --- |
| 저장 안 됨이 확실 | 저장 실패 안내, 변경 내용을 기기에 임시 보관하고 다시 시도 가능 |
| 저장·공개 결과 불명 | 서버 현재 상태와 해당 작업의 반영 여부를 확인. 이미 반영됐다면 성공 처리, 반영되지 않았다면 재시도 |
| 공개 실패가 확실 | 저장된 작업본 유지, 이전 공개본 유지. 최초 공개 실패라면 계속 공개 전 상태 |
| 공개 성공·알림 실패 | 공개 성공과 실패한 알림 수를 구분하고 알림만 재전송. 공개를 다시 실행하지 않음 |

동일 작업 재시도는 변경·공개를 중복 반영하지 않아야 한다. 최신 값이 같다는 이유만으로 해당 요청의 성공을 확정하지 않으며 작업 식별·결과 확인의 상세 계약이 필요하다. 공개 성공 후 알림 실패로 공개본을 되돌리지 않는다.

임시 보관 구현 방식·보관 기간·기기/계정 범위·민감정보 처리·로그아웃 및 권한 회수 후 복구, 중복 방지 key·TTL·response replay·알림 실패 건 추적은 후속 기술 계약이다. 이번 제품 요구만으로 localStorage에 개인정보를 저장하는 구현을 결정하지 않는다.

## 변경 기록과 되돌리기

변경자·시간·대상·변경 전후를 기록한다. 공개 기록의 구체적인 필드·형식은 상세 설계에서 정한다.

되돌리기는 현재 상태에서 역변경을 계산하고 영향·충돌을 확인한 후 **새로운 작업 변경**으로 저장한다. 필요하면 별도 공개한다. 과거 편성 전체를 강제 복원해 이후 정상 변경을 없애지 않는다. 현재 참가 자격·권한 검사를 유지하므로 되돌리기로 취소자 배정·조장 접근을 자동 복구하지 않는다.

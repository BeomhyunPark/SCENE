## Export 권한과 최소 범위

| 사용자 | Export 기준 |
| --- | --- |
| Event Owner | 해당 행사 범위 |
| Organization Owner | 조직 관리·복구 목적 |
| 일반 운영자 | 명시적으로 받은 Export 권한·대상 범위 |
| 일반 조장 | 기본 허용하지 않음. 조원 전체 조회가 Export를 자동 부여하지 않음 |
| 참가자 | 자기 정보 다운로드는 별도 Self-service 검토. 행사 전체 Export와 구분 |

조회와 Export 권한을 분리한다. 목적·대상·필드 범위를 선택하고 필요한 컬럼만 포함한다. 전체 데이터 반출을 기본값으로 사용하지 않는다. 민감정보 포함은 추가 확인을 받는다. 해당 행사·현재 권한·필드 범위를 서버에서도 검사한다.

## 생성·다운로드 기록

개인정보 또는 내부정보 Export에 실행자·시각·조직/행사·목적·대상/필드 범위·정보 등급·건수·성공/실패를 기록한다. Export 생성과 실제 다운로드를 구분하며 파일 내용을 로그에 복제하지 않는다.

민감 Export의 재인증 또는 추가 확인, 만료 다운로드·영구 공개 URL 금지·다운로드 이벤트 기록 방향을 따른다. 정확한 확인 수단·파일 수명·발급/다운로드 시 권한 재검사·재사용/회수·저장소·job 계약은 #12에서 정한다.

## 데이터별 보존 목적

| 종류 | 처리 방향 |
| --- | --- |
| 참가자 개인정보·신청 응답 | 행사 운영·필요한 후속 처리 목적이 끝나면 삭제 또는 익명화 |
| 운영 기록 | 운영 구조·결정·회고 등 필요한 기록 유지, 불필요한 개인 연결 제거 |
| 정산 기록 | 입금 확인 등 운영 상태와 실제 결제/회계/세무 증빙을 구분. 실제 취급 시 별도 근거 확인 |
| Audit/Security | 사고 조사·보안·책임 추적 목적의 독립 lifecycle. 행사 삭제와 동시에 무조건 삭제하지 않음 |

ARCHIVED는 모든 개인정보의 무기한 보존 근거가 아니다. 감사 기록도 무기한 보존으로 결정하지 않는다. 과거 배정 기록·신청 revision·공지 대상·첨부·자유서술·로그의 잔존 개인 연결도 처리 범위에 포함해 검토한다. 건강정보·여권 등 예시는 향후 취급 가능성 검토이며 새로운 수집 기능 확정이 아니다.

## 보관·익명화·삭제

- 보관: 읽기 전용 과거 행사 관리 상태. 데이터는 보존 정책을 따르며 정책상 보관 해제 가능.
- 익명화: 재식별이 필요 없는 형태로 처리하고 일부 운영 통계/구조 유지. 원칙적으로 되돌릴 수 없음. 이름 제거만으로 실질 익명화 완료를 주장하지 않음.
- 최종 삭제: 대상 데이터 제거 후 일반 서비스에서 조회·복구 불가. Soft delete를 삭제 완료로 표현하지 않음.

사용자에게 행사 보관·개인정보 정리·행사 데이터 삭제 같은 목적 있는 행동을 제공한다. 법적/보안상 보존이 필요한 기록을 임의 선택해 지우는 DB 청소 도구를 제공하지 않는다. 보존 예외는 근거·범위·처리 방식을 안내한다.

## 삭제 영향·권한·복구

삭제 전 영향 데이터·건수와 유지 데이터·사유, 복구 불가 여부를 보여주고 명시적 확인을 받는다. 참가자와 배정·체크인·정산·History·안내 대상 등 의존 관계를 검사해 삭제·익명화·참조 제거·필요 보존을 적용한다. 참가자 row 한 개 삭제로 완료 처리하지 않는다. 구체적 FK/CASCADE·transaction/process·실패/부분 처리 계약은 #12 후속이다.

행사 전체 최종 삭제를 Organization Owner로 제한하고 Event Owner가 요청하는 안은 사용자 본문의 **제안**이다. 최종 7개 결정 요약에는 실행권이 지정되지 않아 #12에서 승인/실행권과 개인정보 정리·익명화 권한을 명시한다. Event Owner의 종료·보관 권한만으로 영구 삭제 권한을 자동 부여하지 않는다.

최종 삭제·실질 익명화 후 일반 복구는 제공하지 않는다. 삭제 유예를 도입한다면 최종 삭제와 구분하고 유예 중 취소 가능 조건을 안내한다. 유예 도입 자체·기간은 아직 미정이며 DELETION PENDING/DELETED를 행사 상태 enum으로 추가하지 않는다.

백업은 재해복구 목적이며 일반 휴지통 복원과 구분한다. 잔존 여부·제한된 기간·접근·최종 소멸·재해복구 후 파기 재적용 계약을 확인하기 전 구체적 복구나 소멸 시점을 약속하지 않는다.

## 기간·근거·후속

참가자/고위험 개인정보, 정산 증빙, 접근/Export/Audit 기록, 계정·조직 탈퇴, 삭제 유예, 백업 소멸, 미성년/보호자 정보 기준은 실제 처리 목적·적용 법령·계약·운영 필요 근거로 정한다. 7일/30일/5년/7년을 임의 상수로 정하지 않는다.

[개인정보 보호법 제21조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029334901)를 2026-09-30 확인했다. 불필요해진 개인정보 파기, 재생 불가 처리, 다른 법령에 따른 예외 보존의 분리 관리 원칙을 검토 근거로 둔다. 이 조문만으로 모든 데이터의 기간·적용 의무를 확정하지 않는다.

- #10: 목적/필드 선택·추가 확인·생성/다운로드·삭제 영향·복구 불가·보관 해제 구분의 실제 클릭 검토.
- #11: 행사 전용 운영자에게 Export 업무 권한을 부여·회수하는 계약과 결합.

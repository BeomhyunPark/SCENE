## 저장과 공개

저장은 운영자의 작업을 보존한다. 별도 **참가자에게 공개** 실행 전까지 참가자·일반 조장에게 편성 초안을 보여주거나 안내를 발생시키지 않는다. 편집 중인 Working State와 대상자가 보는 Published State를 구분한다.

| 운영 화면 상태 | 의미 | 참가자·일반 조장 |
| --- | --- | --- |
| 준비 중 | 아직 공개본 없음 | 편성 준비 중 안내 |
| 공개 중 | 현재 공개본 있음 | 현재 공개본 조회 |
| 미공개 변경 있음 | 공개 후 작업본 수정 | 직전 공개본 조회. 다시 공개할 때 갱신 |

운영 화면에는 마지막 공개 시각·미공개 변경 건수·참가자가 이전 편성을 보고 있다는 안내·변경사항 공개 행동을 제공한다. 조 이동 저장만으로 공개본을 바꾸지 않는다. 공개 실행은 편성을 한 번에 반영해 재편성 도중의 중간 상태를 보여주지 않는다.

Working/Published는 제품 개념이다. 두 벌 저장·버전·스냅샷 중 어느 구현을 쓸지, 변경 건수를 어떤 단위로 계산할지, 공개 권한의 Permission 이름·부여자는 아직 정하지 않았다.

## 일부 배정과 공개 확인

부분 배정·미배정이 남아 있어도 저장한다. 배정 완료율을 저장 조건으로 강제하지 않는다. 이 기준이 인증·업무 권한·대상 소속·데이터 유효성 검사를 생략한다는 뜻은 아니다.

공개도 허용하되 활성 참가자 중 미배정자의 수와 영향을 경고하고 명시적 확인을 받는다. 예를 들어 38명 배정·4명 미배정이면 배정자는 자기 조를 보고 미배정자는 아직 미배정 안내를 본다는 점을 알려준다.

취소 참가자는 완료 검사와 공개 참가자·조장 명단에서 제외한다. 부분 참석이라는 이유로 공개를 막지 않고 배정된 부분 참석자는 일반 배정과 동일하게 공개한다. [#7 확정 정책](group-change-recovery-review.md)에 따라 이후 취소도 재공개 대기 없이 활성 편성·공개 명단·조장 조회에서 즉시 제외한다. 과거 기록은 보존하고 복귀 시 자동 배정을 복원하지 않는다.

## 공개와 안내 대상

공개는 공식 공개 상태를 갱신하는 일이고 알림은 사람에게 변경 사실을 전달하는 일이다. 내부 저장은 참가자 안내를 발생시키지 않는다.

- 최초 공개: 대상 참가자·조장에게 안내한다.
- 변경 공개: 실제 영향받는 참가자와 기존·신규 조장에게 안내한다.
- A를 1조에서 3조로 옮겼다면 A·기존 1조 조장·신규 3조 조장이 안내 대상이다. 전체 참가자에게 일괄 안내하지 않는다.

실제 전달 채널은 별도 결정한다. 제품은 변경에 따른 안내 대상을 식별해야 한다. #7에서 공개 실패·결과 불명·알림 실패를 구분하고 재시도 중복 방지를 확정했다. 공개 성공·알림 실패는 공개본을 유지하며 알림만 다시 보낸다. key·TTL·전달 채널 등 상세 기술 계약은 후속이다.

## 참가자·조장 조회

| 대상 | 편성 조회 | 정보 범위 |
| --- | --- | --- |
| 일반 참가자 | 자기 공개된 배정 | 자기 조·조장·집합 장소 등 참가자용 정보. 다른 사람의 개인정보·전체 명단을 자동 공개하지 않음 |
| 일반 조장 | 공개된 자기 조 명단 | #3에서 확정한 자기 조원의 전체 정보·리더용 정보. 다른 조 명단 제외 |
| 편성 업무 권한을 가진 운영자·조장 | 준비 중 작업본 | 부여된 업무 권한과 행사 범위에 따름 |

조장 역할만으로 작업본 접근·수정·공개 권한을 추가하지 않는다. #3의 조직 관리자 전체 조회와 별도 수정 권한 원칙은 유지하며, 겸임 역할의 작업본 조회·공개 범위는 후속 Permission 계약에서 대조한다.

참가자 화면은 **공개 전 준비 중 / 공개됐지만 아직 미배정 / 현재 배정**을 구분한다. 공개된 배정에는 마지막 갱신 시각을 제공한다. 조원 범위는 공개된 편성 기준으로 판단해야 하며 작업본의 이동만으로 일반 조장 명단을 바꾸지 않는다. 취소·현재 권한 회수는 재공개를 기다리지 않고 조회 범위에 반영한다. 일반 이동의 이전·신규 조장 범위는 공개 시 전환한다. 상세 판정 방식은 [변경·복구 검토](group-change-recovery-review.md)를 따른다.

## 문서·Figma·후속 범위

- P16 작업본 저장과 P18 참가자 안내 사이에 별도 공개가 필요하다는 정책 주석을 반영한다.
- #7: [변경·취소·동시 수정·실패·재시도 제품 정책 확정](group-change-recovery-review.md). 세부 기술 계약은 후속.
- #10: 공개 확인·미공개 변경·세 가지 참가자 상태·조장 범위의 실제 Present 클릭 검토.
- API: 기존 Group 변경은 작업본 변경으로 해석하고 참가자 Group 조회는 공개본만 반환한다. 공개 endpoint·DTO·snapshot schema는 후속 설계한다.

정책 주석 반영은 공개 기능이나 알림 구현 완료를 뜻하지 않는다. P16의 내부 운영 화면 상태와 P18의 참가자 공개 상태를 같은 데이터로 연결했다는 이유만으로 검토를 완료하지 않는다.

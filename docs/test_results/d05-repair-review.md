# D05 신청 변경 안내의 상태 유지

상태: Review. [이슈 #17](https://github.com/BeomhyunPark/SCENE/issues/17), 상위 감사 #10.

## 원인과 수정

신청 마감 화면은 변경 시 운영팀에 문의하라고 안내했지만 그 상태가 인증 후까지 전달되지 않아 정상 수정 화면에서 직접 저장할 수 있었다.

현재 운영팀 문의로 안내하는 진입 경로에 직접 수정 허용 상태를 추가했다. 해당 경로는 인증·휴대폰 변경 후에도 직접 수정 불가 상태를 유지한다. 내 신청의 행동과 설명이 변경 안내에 맞게 표시되고, 변경 안내·기간 안내·직접 저장은 같은 제한을 따른다. 직접 저장을 차단할 때 기존 참석 정보는 변경하지 않는다.

정상 수정 가능 진입 경로는 편집·저장 흐름을 유지한다. 취소된 신청 조회도 기존 취소 상태 흐름을 유지한다.

## 검증

저장된 reactions 및 안내 바인딩을 다시 읽어 검사한 22개 시나리오 모두 통과했다. 결과는 `d05-reaction-check.json`, 재현 코드는 `d05-reaction-check.figma.js`다. 재현 코드는 Figma use_figma 문맥에서 실행하며 캔버스나 변수 기본값을 수정하지 않는다.

`d05-repair-guidance.png`는 캔버스 캡처다. 실제 Present 클릭, 서버 권한·저장·시간 검증은 수행하지 않았다. 원본 감사는 수정 전 증거로 유지한다.

## 미결 정책 O01

신규 신청 마감과 기존 신청 수정 마감의 관계, 수정 가능한 필드와 시한은 미결이다. 이번 수정은 현행 운영팀 문의 안내와 동작을 일치시킨다. 모든 신청 마감 상태의 수정을 일괄 금지하는 제품 정책으로 확정하지 않는다.

## 종료 전 검토

- [ ] 마감 → 내 신청 확인 → 인증 → 변경 안내 → 내 신청 복귀를 Present에서 재현한다.
- [ ] 직접 저장 제한, 전화번호 변경·기간 안내 후 제한 유지와 정상 수정 경로를 확인한다.
- [ ] O01 수정 허용 범위·기간을 확정한 뒤 안내 및 상태 조건을 재검토한다.

- `../483-ui-clutter-audit/capture.mjs <dir> <prefix> <화면들>`: 화면 전체를 1440·390(deviceScaleFactor 2)으로 찍었다. `before/`(시작 전), `after/`(고친 뒤).

숨긴 메뉴는 `frontend/src/components/operatorMenu.ts`의 메뉴 정의에 `pending: true`만 붙였다. 그 표시를 지우면 다시 보인다. 주소(`/history` `/guides` `/schedule` `/integrations` `/events/:id/areas`)와 준비 중 화면은 그대로라 저장된 주소로 들어오면 안내가 보이고, 그때 사이드바에는 현재 위치 표시가 없다. 숨기고 비는 묶음은 구분선째 빠진다. 행사 홈에는 "다른 기능 시작"으로 가는 다른 길이 이미 없다(`EventHome.test.tsx`).

## Figma와 다르게 둔 것

- 사이드바: Figma 사이드바(`RreFdEVMiwgHrV7teaCEOm` 1325:5059 등)에는 기록·안내·일정·연동·다른 기능 시작이 있다. 화면이 없는 동안 숨기기로 사용자가 정했다(2026-11-25). `docs/product/operator-sidebar-menus-review.md`에 기록했다.
- 새 문구는 만들지 않았다. 남긴 문구는 모두 원래 있던 것이다("읽지 않은 알림 N개", "고정 N/3", "아직 준비 중이에요").
- 이번에 Figma를 새로 열어 대조하지는 않았다. 메뉴·프레임 유무는 #483 조사표와 사이드바 결정 기록의 확인 결과를 따랐다.

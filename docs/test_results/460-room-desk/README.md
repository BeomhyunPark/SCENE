## 단계

1. `1-table-room-column` 참가 현황 표: `조 배정` 다음에 `방` 열이 기본으로 보인다. 301호·301호·302호·**302호(최예린, 작업본은 301호)**·숙박 안 함·**미배정(한늦게, 작업본은 302호)**. 합계 줄 "배정 4 · 2개 방 · 숙박 안 함 1"
2. `2-table-not-lodging-filter` 필터 → 방: 보기 "301호 2 · 302호 2 · 숙박 안 함 1 · 미배정 1", 숙박 안 함을 고르면 1명
3. `3-field-roster-rooms` 현장 운영 명단: 이름 아래 "방 301호 · 본관 3층 왼쪽" 등, 정집회는 "숙박 안 함", 한늦게는 줄이 없다
4. `4-field-checkin-notice` 김하늘 체크인 → 알림 "94 김하늘 님을 체크인했어요. 방: 301호 · 본관 3층 왼쪽". 정집회 체크인 → "98 정집회 님을 체크인했어요. (숙박 안 함)"
5. `5-field-after-republish` 다른 운영자처럼 API로 다시 공개 → 10초 자동 새로 읽기 뒤 최예린 "방 301호 · 본관 3층 왼쪽", 한늦게 "방 302호 · 본관 3층 오른쪽"

CSV는 같은 서버 응답을 `server-response.json`의 `csvHeaderAndRoomCells`(제출 시각·이름·마지막 `방` 칸)로 남겼다: 301호·301호·302호·302호·숙박 안 함·빈칸.

## 하지 못한 것

- 운영 서버와 실제 휴대폰 확인
- QR 스캔 결과의 방은 카메라가 없어 실제로 누르지 못했다. 컴포넌트 테스트(`RoomDesk.test.tsx`)와 서버 통합 테스트(QR 체크인 응답의 `room`)로만 확인했다

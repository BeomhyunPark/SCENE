# D04 미배정 참가자 추가 배정

상태: Review. [이슈 #16](https://github.com/BeomhyunPark/SCENE/issues/16), 상위 감사 #10.

## 원인과 수정

기존 86/104 저장 완료 보드는 미배정 이름에 반응이 없었고, 기존 배정 모달은 김민수의 첫 배정 전용이었다.

표시된 6명(민서윤·정예린·송태훈·이주원·박다은·정지후)을 조 선택 모달에 연결했다. 1조 또는 2조 선택 후 검토 모달에서 대상과 저장 후 인원수를 확인한다. 최종 저장 전에는 현재 편성에 반영되지 않으며 취소는 기존 상태를 유지한다.

저장하면 선택한 참가자만 미배정 목록에서 사라지고 선택한 조에 표시된다. 조 인원수와 배정/미배정 수가 함께 바뀐다. 동일 참가자의 중복 저장은 인원수를 늘리지 않는다. 6명을 연속으로 배정할 수 있으며 행사 홈·참가 현황·조 상세에서도 저장 결과를 유지한다.

기존 컴포넌트·폰트·변수 스타일을 재사용했다. 모달 버튼이 컨테이너 안에 들어오도록 너비를 조정하고 보드 본문에 세로 스크롤을 설정했다. 변경 후 정확히 계산하지 않은 기존 시간대 요약은 새 보드에서 제거했다.

## 검증

저장된 reactions 및 변수 바인딩을 다시 읽어 평가한 82개 검사가 모두 통과했다. 양쪽 조 선택, 취소, 조 다시 선택, 중복 저장, 6명 연속 배정, 한 조에 6명 모두 배정, 명단 표시, 참가 현황·홈 복귀를 검사했다. 모달 버튼 6개의 경계 검사와 보드 본문의 스크롤 설정도 확인했다.

결과는 `d04-reaction-check.json`, 재현 코드는 `d04-reaction-check.figma.js`다. 재현 코드는 Figma use_figma 문맥에서 실행하며 캔버스나 변수 기본값을 수정하지 않는다. `d04-repair-chooser.png`, `d04-repair-review.png`, `d04-repair-board.png`는 기본 변수값의 캔버스 캡처이며 실제 클릭 후 캡처가 아니다.

실제 Present 클릭, 서버 저장·권한·동시성은 검증하지 않았다. 범위는 기존 86/104 저장 완료 보드의 표시된 6명과 1조/2조 선택이다. 나머지 참가자·조 및 D03 첫 배정 보드의 추가 배정은 별도 범위다. 원본 감사 파일은 수정 전 증거로 유지한다.

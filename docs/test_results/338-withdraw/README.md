행사·신청서·신청 3명·조 배정·조장·공개·도착 체크인은 HTTP API로 만들고(같은 운영자 세션, 신청은 사람마다 다른 휴대폰 컨텍스트), 취소·목록·되돌리기·참가자 들어오기는 화면에서 눌렀다.

## 단계

1. `01` 운영자 표: 3명, 이나래는 1조 조장, 도착 체크인함
2. `02`~`03` 휴대폰 폭(390) 서랍의 "현재 참가 상태" → 신청 취소 → 확인 창(조 배정·조장 표시가 풀림, 체크인 기록은 남음, 세션 끊김, 되돌려도 조는 다시 정함), 사유 입력
3. `04` 서랍이 닫히고 안내. 숫자: 집계 3→2명·2일 밤 3→2·자차 1→0, 체크인 1/3→0/2, 명단 3→2, 편성판 3→2(취소 1), 공개본 1조 3→2명·조장 1→0, 다른 조원이 보는 조장 "이나래"→없음, 표 3→2, CSV 3→2
4. DB: 신청 `WITHDRAWN`, 조 이력 `WITHDRAWN`(조장이었음), 세션 0, audit에 사유 없음
5. `05` 표의 "취소 1" → 취소된 신청(누가·언제·사유·이전 조, 되돌리기)
6. `06` 신청 집계, `07` 조 편성, `08` 현장 운영 화면(취소 뒤)
7. `09` 이나래 휴대폰: 남은 쿠키로 열면 들어오기 화면, 맞는 값으로 들어와도 "…신청이 취소되었다면 운영진에게 문의해 주세요."
8. `10` 신청 상세의 "취소된 신청"
9. `11`~`12` 되돌리기 확인 창 → 표 3명. 숫자가 모두 취소 전으로 돌아오고, 이나래는 미배정, 공개본에서도 미배정(아래)
10. `13` 이나래가 다시 들어옴

## 실제 클릭에서 찾아 고친 것

- **되돌린 조장이 이전 공개본에서 예전 조의 조장으로 다시 보였다.** 공개 스냅샷에 취소 전 배정이 남아 있어서다(DEC-044 위반). 공개본을 읽을 때 그 공개 뒤에 취소로 배정이 지워진 사람을 스냅샷에서 빼도록 고쳤다(DEC-084 §3). 고친 뒤 `click-log.txt`의 "되돌린 후"는 공개본 1조 2명·조장 0이다.
- **휴대폰 폭에서 표의 "수정" 버튼이 작업 칸에 잘려 눌리지 않았다**(#337부터 있던 문제). 작업 칸을 128px → 144px로 넓혔다.

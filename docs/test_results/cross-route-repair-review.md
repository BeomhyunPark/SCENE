# 화면을 벗어난 뒤의 상태 유지 재수정

브랜치: `fix/prototype-cross-route-state`. 사용자 재검토에서 발견한 화면 간 연결 결함을 수정했다. 기존 감사·수정 검증 결과는 당시 검사 범위의 증거로 보존하며 최신 결과와 구분한다.

| 항목 | 원인 | 수정 |
|---|---|---|
| D12 · #24 | 목록과 회고의 공통 버튼이 완료 샘플을 참조 | 미완료 종료 상태에 따라 종료 홈 840:44470과 0/2 기록 840:44530으로 복귀. 원래 완료 종료는 해당 상태를 명시적으로 해제 |

D03·D04의 첫 저장 흐름은 현재 존재하는 1조와 표시된 6명만 다룬다. 다른 86/104 샘플의 1조/2조 배정은 기존 흐름으로 유지한다. 상세 권한·실제 데이터 저장과 104명 전체 편성은 이번 프로토타입 검증에 포함하지 않는다.

## 증거와 검증 범위

- [새 경로 평가](cross-route-reaction-check.json): 80/80 통과. [Figma 실행 스크립트](cross-route-reaction-check.figma.js)는 저장된 반응을 읽어 메모리에서 상태 전이를 평가한다.
- [기존 검사 재실행](cross-route-existing-checks.json): D01 25, D02 24, 기존 D04 82, D05 22, D06–D12 48 = 201/201 통과.
- 기존 D03의 고정 화면/연결 15개 검사는 최초 스냅샷 증거다. 조 상세 목적지와 동적 문구가 바뀌었으므로 최신 연속 배정 검사가 이를 대체한다. 최초 결과를 현재 상태의 재검증으로 세지 않는다.
- 일반 화면: [첫 저장 보드](cross-route-first-board.png), [수정 가능 안내](cross-route-editable-guidance.png), [요청 예외 안내](cross-route-request-guidance.png), [취소 안내](cross-route-cancelled-copy.png).
- 누적 배정 배치: [7명 보드](cross-route-seven-member-board.png), [7명 상세](cross-route-seven-member-detail.png). 시각 확인을 위해 변수 기본값과 연결된 텍스트를 7명 상태로 일시 설정한 캡처다. 실제 Present에서 버튼을 6번 클릭한 캡처가 아니다. 확인 뒤 1/104 기본값과 원래 바인딩을 복원했다.
- 사용된 글꼴은 기존 Noto Sans KR·Inter·Geist를 유지한다.

실제 Present 클릭, 브라우저 뒤로 가기, 새 세션, 실제 인증·저장·초대·Export 서버 호출은 수행하지 않았다. 저장된 분기와 바인딩 평가가 실제 실행 성공을 보장하지 않는다. 이슈와 프로젝트는 Review를 유지한다. O01 정책과 #11·#12의 실제 계약 검증도 그대로 남는다.

## 실제 Present에서 이어서 확인할 경로

1. 미완료 MT 종료 → 행사 목록 → 행사 기록 → 회고 → 저장 → 준비 기록 → 종료 홈. 0/2 유지 확인.
2. 첫 편성 저장 → 박서연 저장 → 이도현 저장 → 참가 현황/홈/1조 상세 왕복. 누적 3/104 및 이전 명단 유지 확인.
3. 정상 신청 인증 → 수정 가능 안내 → 내 신청 → 수정 → 저장. 제한 경로에서는 문의 안내와 저장 차단 확인.
4. 일정 → 공용 물품 정리 → 뒤로, 진행 시작 → 뒤로, 일정에서 재진입. 로비 업무도 그대로 일정으로 복귀하는지 확인.
5. 가입 승인·거절 예외 진입과 취소된 신청 문구 확인.

재수정 자료는 `fix/prototype-cross-route-state` 브랜치에서 경로 검증 결과, 화면 캡처, 검토 문서로 나눠 버전 관리한다. 실제 검토 완료 여부는 관련 이슈와 프로젝트 Review 상태로 추적한다.

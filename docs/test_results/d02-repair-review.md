# D02 모바일 준비 업무 상태 유지

상태: Review. [이슈 #14](https://github.com/BeomhyunPark/SCENE/issues/14)는 감사 #10의 하위 수정 작업이다.

## 원인과 수정

로비 안내 표지 준비의 진행·체크 완료·업무 완료 화면은 별도 고정 화면이었다. 일정 화면의 업무 버튼이 초기 상세로 고정되어 완료 후에도 1/2로 되돌아갔다.

모바일 흐름에 ONE / CHECKED / DONE 공통 변수를 추가했다. 업무 완료, 명시적 다시 진행, 체크 해제 시 해당 상태를 변경하며, 일정 상태 표시와 업무 상세 진입·첨부 복귀는 현재 상태를 따른다. 완료 화면 체크는 명시적 재개 전까지 읽기 전용이다.

## 검증과 범위

저장된 Figma reactions를 다시 읽어 평가한 24개 시나리오 모두 통과했다. 결과는 `d02-reaction-check.json`, 재현 코드는 `d02-reaction-check.figma.js`에 있다. 이 코드는 Figma use_figma 문맥에서 실행하며 화면 및 변수 기본값을 수정하지 않는다.

현장 홈 5개 일정 진입 경로, 완료·2/2 유지, 첨부 복귀, 명시적 재개·체크 해제를 검사했다. `d02-repair-schedule.png`는 기본 진행 상태의 캔버스 캡처이며 완료 후 실제 Present 캡처가 아니다.

이번 검증은 조건·변수·목적지 평가다. 실제 Present 클릭, 서버 저장, 새 세션의 상태 복원은 검증하지 않았다. 모바일 로비 업무 흐름을 수정했으며 태블릿 고정 검토 화면은 별도다. 일정 출발 후 뒤로 가기 목적지 문제는 이후 [D11 수정 검토](d11-repair-review.md)에 기록했다.

## 종료 전 검토

- [ ] Present에서 업무 완료 → 내 업무 → 현장 운영 → 오늘 일정 → 동일 업무를 클릭한다.
- [ ] 일정의 완료·2/2 표시와 완료 상세 체크 2/2를 캡처한다.
- [ ] 명시적 재개·체크 해제 및 첨부 복귀를 재검토한다.

원본 감사 파일은 수정 전 증거로 유지한다.

판정 기준과 검토 한계

  • PASS: 실제 Present에서 조작하고 도착 화면·표시 상태를 확인한 범위만 해당. 화면 연결 PASS는 계정 생성·SMS·저장 API·권한 서버 검증의 PASS를 뜻하지 않음.
  • DEFECT: 확정 정책과 다른 실제 전이, 명시된 조작의 무반응, 상태 유실, 필수 경로 누락. D07~D10은 실제 경로에서 확인한 UI 요구사항 누락이며 존재하지 않는 버튼 클릭으로 기록하지 않음.
  • POLICY OPEN: 앞선 결정으로 해결되지 않은 판단. 이미 확정된 규칙의 미구현은 이 분류로 돌리지 않음.
  • NOT TESTABLE: 실행 비활성·상태 주입 불가·연결된 역할/데이터 fixture 부재·서버 또는 시간 경과 검증 필요. ‘없다’는 결론은 탐색한 경로 범위로 한정.
  • Figma Flow 선택은 테스트 초기 조건 설정. 제품 동작 PASS에서 제외. Next Frame 이동·정적 구조·정책 주석을 기능 검증 증거로 사용하지 않음.
  • 실제 제품 버튼을 클릭한 뒤 URL의 node-id와 안정된 화면 확인. 전환 중 일시적 검은 화면은 결함에서 제외. 동일 화면 ID에서도 모달·변수 변경 확인.
  • 요청된 대표 경로와 정책 분기를 판정표로 전수 매핑했으나, 미연결 경로까지 실행 완료한 것은 아님. Tablet·연구용·과거 화면 전체의 모든 버튼은 본 요청의 모바일 중심 대표 흐름 통과 근거에 포함하지 않음.

결함 — 재현·기대·실제·수정 기준

P0: 잘못 구현하면 권한/책임 정책 기반이 바뀌므로 해당 개발 착수 전 수정. P1: 기반 정책을 확정한 뒤 UI·연결·상태 구현 단계에서 수정 가능하나 해당 기능 인수 전 필수. P2: 문구·복귀 맥락 등 후속 개선. 우선순위는 이번 감사의 제안이며 사용자 승인된 우선순위가 아님.

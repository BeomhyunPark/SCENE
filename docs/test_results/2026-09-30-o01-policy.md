# O01 신청 수정 정책 반영·검증

2026-09-30 사용자 승인으로 [DEC-028](../product/PRODUCT_DECISIONS.md#dec-028--o01-신규-신청-마감과-자기-신청-수정-마감-분리)을 CONFIRMED로 기록했다. 신규 신청·수정 마감 분리, 수정 마감 전 이름·참석 범위 변경, 새 휴대폰 번호 재인증 후 저장, 수정 마감 이후 운영팀 문의를 적용한다. 행사별 실제 마감 시각은 이번에 정하지 않았다.

## Figma 반영

파일: `RreFdEVMiwgHrV7teaCEOm`, 페이지: `262:7`.

- 기존 `VariableID:826:44310`의 이름을 `D05/editDeadlineOpen`으로 변경했다. ID는 유지한다. 신규 신청 진입 화면이 이 값을 true/false로 덮어쓰지 않도록 수정했다.
- `D05/registrationOpen`은 신규 신청 안내의 복귀 경로만 구분한다. 수정·저장 허용 여부는 별도 수정 마감 상태와 신청 취소 여부로 판정한다.
- 신규 마감 화면, 수정 가능 안내, 운영팀 문의, 편집 안내 문구를 정책에 맞췄다.
- 이름·참석 범위의 초안과 저장 상태를 연결했다. 내 신청 표시와 취소 상세의 이름·휴대폰 표시를 저장 값에 바인딩했다. 편집 진입은 저장 값을 불러오고, 저장하지 않고 뒤로 가면 초안을 폐기한다.
- 휴대폰 필드 클릭은 고정 fixture 새 번호 `010-0000-0000`으로 변경하고 인증 화면으로 이동한다. 미인증 저장은 인증으로 되돌리며, 인증 확인 후에만 번호 변경을 저장한다. 기존 내 신청 조회 인증과 번호 변경 인증의 문맥을 구분한다.
- Figma가 중첩 조건 액션을 거부하므로, 클릭 시작 때 조건값을 스냅샷 변수에 저장한 뒤 독립적인 두 블록 조건 액션으로 실행한다. 상태 변경 때문에 같은 클릭에서 다음 분기가 잘못 실행되지 않게 한다.

[반영 스크립트](../design/o01-figma-policy-update.figma.js)는 라이브 Figma에 쓰며 O01 fixture 기본값을 초기화한다. 읽기 전용 검증 스크립트와 다르므로 자동 실행하지 않는다. 새 화면·컴포넌트는 만들지 않고 기존 화면·필드를 재사용했다.

## 실제 Present 클릭 결과

Chrome에서 클릭 후 도착 화면·URL·표시 문구를 관찰했다. 다음 경로에서 실패를 발견하지 않았다.

| 경로 | 실제 관찰 |
| --- | --- |
| 신규 마감 안내 → 조회·인증 → 내 신청 → 편집 | `395:31032` → `395:30763` → `395:30800` → `395:30836` → `395:30885`. 신규 마감 상태에서도 수정 기간이 열려 있으면 신청 수정 가능 |
| 휴대폰 변경 → 인증 취소 → 변경 저장 | 편집의 새 번호 초안은 유지되지만 저장 완료 대신 `395:30800` 인증 화면으로 되돌아감 |
| 새 번호 인증 확인 → 편집 → 저장 → 내 신청 | `395:30800` → `395:30885` → `395:30927` → `395:30836`. 이름·오후만 참석·마스킹 번호 끝자리 0000 표시. 초안 폐기 보완 후 최종안에서도 재실행 |
| 수정 마감 상태에서 편집 화면 직접 진입 → 저장 | `editDeadlineOpen=false`를 임시 기본값으로 주입한 새 세션에서 `395:30885` → `826:44314`. 수정 마감·운영팀 문의 안내 확인. 테스트 후 기본값 true 원복 확인 |
| 이름 변경 → 편집 뒤로 가기 → 재진입 | `395:30885` → `395:30836` → `395:30885`. 김민수 원본 유지, 초안의 김민서 폐기 |
| 이름·참석 범위 변경만 저장 → 내 신청 | 김민서·오후만 참석 표시, 기존 번호 끝자리 1034 유지. 불필요한 번호 인증 없이 저장 |

마감 상태 주입과 인증은 프로토타입 fixture다. 실제 번호 입력·SMS·서버 인증·DB 저장은 수행하지 않았다. 이름 필드 클릭은 고정 김민서 fixture로, 참석 범위 클릭은 오후만 참석으로 바뀐다. 자유 입력·모든 참석 옵션 구현으로 해석하지 않는다. 화면 캡처는 도구 출력에서 관찰했으며 저장소에 PNG나 녹화 파일을 첨부하지 않았다.

## 저장 구조 조건 검사

[검사 스크립트](o01-policy-check.figma.js)는 저장된 Figma 액션을 읽어 메모리에서 SET_VARIABLE·CONDITIONAL·NODE를 순서대로 평가한다. [실제 검사 결과 JSON](o01-policy-check.json): **29/29 통과**.

- 저장: 수정 마감·취소·번호 변경 대기·새 번호 인증 여부 16개 조합.
- 인증: 조회/번호 변경 문맥·수정 마감·취소 여부 8개 조합.
- 진입: 신규 마감/정상 진입과 수정 마감 4개 조합. 진입이 수정 마감 값을 덮어쓰지 않고 라벨을 맞추는지 검사.
- 편집 초안 폐기 1개 조합.

이는 실제 Present 29번 클릭이나 서버 테스트가 아니다. 과거 14개 수동 검사 및 80/80·201/201과 합산하지 않는다. 기본값은 수정 기간 열림, 번호 변경 대기·인증·인증 문맥 모두 false로 확인했다.

## 남은 구현·검토 범위

서버 시간 경계, 행사별 마감 설정 UI, 새 번호와 인증 결과 연결, 인증 오류·만료·재발송 제한, 자유 입력·모든 참석 옵션, 신청 수정의 운영자 이력 반영은 아직 실제 구현·검증하지 않았다. 마감 중 인증 완료를 시도하는 경우는 조건 검사에 포함했지만 실제 시계가 지나가는 Present 테스트는 아니다. 취소 상세의 새 바인딩은 구조 검사만 수행했으며 변경 후 취소 경로 전체를 다시 클릭하지 않았다.

O01 정책 미결은 해소됐지만 정책 승인과 변경된 Figma의 사용자 검토는 별개다. #17은 새 동작 검토 대상으로 Review / open을 유지한다.
